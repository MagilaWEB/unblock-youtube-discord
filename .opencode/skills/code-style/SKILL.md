# code-style (unblock)

Структурный стиль C++ в этом проекте. clang-format выравнивает, этот скил — про то,
что формат не ловит. Обоснование — читаемость и корректность (время жизни, RAII),
а не производительность: на кэши и кодогенерацию область видимости не влияет.

## Локальные — в самом узком блоке
- Новую переменную, нужную только для проверки, объявлять прямо в условии, а не
  отдельной строкой над ним. Плохо:
      const auto aboba = getValue();
      if (aboba) { ... }
  Хорошо:
      if (const auto aboba = getValue()) { ... }
  (если значение не приводится к bool — init-statement: `if (const auto aboba = getValue(); aboba > 0)`)
- Не поднимать локальные на верх функции «на будущее».

## Не плодить лишние строки
- Присваивание, за которым сразу идёт проверка, — прямо в условие:
      if (!(settled = autoRoundSettled(...))) { ... }
- Не заводить временную ради одного использования — сворачивать в выражение:
      if (technology == Technology::Zapret2 ? _runPassiveRound(...) : _runTestingRound(...)) { ... }
- Именовать temp только если выражение используется ≥2 раз или реально улучшает
  читаемость (`const auto it_next = it + 1;` — идёт и в сравнение, и в разыменование).
- Одна пустая строка отделяет логически разные блоки: после ранних выходов,
  перед завершающим `return` (отделить его от основной работы), между
  независимыми группами операторов. Не лепить пустую строку после `{`, между
  каждой парой строк или после каждого `return` подряд.
- Пустая строка всегда одна: clang-format (`MaxEmptyLinesToKeep: 1`) сохраняет
  ровно одну, лишние схлопывает, а строку сразу после `{` удаляет.

## Приоритет
- Формат — на clang-format; этот скил — про структуру кода.
