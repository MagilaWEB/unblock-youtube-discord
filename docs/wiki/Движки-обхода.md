# 🔀 Движки обхода

В Unblock встроены две технологии обхода. Обе работают на движках bol-van, но по-разному: одна перебирает стратегии на живом трафике, вторая запускает готовые статичные профили. Селектор движка — на вкладке Zapret (**🧠 Движок обхода**), одновременно работает только одна.

## Zapret2 (основной)

Запускается как служба `zapret2` — это `binaries/winws2.exe`. Рядом лежит `cygwin1.dll`, без неё движок не стартует. Оба файла взяты из [zapret2](https://github.com/bol-van/zapret2).

Ключевое отличие от классики — обход задаётся не только статичным набором примитивов, но и **Lua-скриптами**:

- `binaries/lua/unblock_auto_strategy.lua` — адаптивный перебор стратегий: смотрит на пакетные улики и переключает стратегию сам (см. [Адаптивные стратегии](Адаптивные-стратегии)).
- `binaries/lua/unblock_signal.lua` — отправка сигналов в unblock и помощнику по UDP.
- Плюс штатные скрипты zapret2: `zapret-lib`, `zapret-auto`, `zapret-antidpi`, `zapret-obfs`, `zapret-pcap`.

Список подключённых скриптов — `configs/lua_init.config`. Стратегии пишутся как `--lua-desync=<функция>:...:strategy=N`, фейк-блобы задаются через `:blob=<ИМЯ>`.

Вместе с движком поднимается служба `zapret2_helper` (`bin/zapret_helper.exe`) — фоновый помощник, который гоняет трафик к хостам и релеит вердикты. Подробно — [zapret-helper](zapret-helper).

Наборы стратегий лежат в `configs/strategy/<поколение>/`; актуальный — с профилями `strategy_super_c` и `strategy_super_d`.

## Классический Zapret

Запускается как служба `zapret1` — это `binaries/winws.exe` из [zapret-win-bundle](https://github.com/bol-van/zapret-win-bundle). Тут обход собран из статичных `--dpi-desync`-примитивов (multisplit, fake, disorder и т.д.), без Lua и без адаптации: что написано в конфиге, тем и режется трафик.

Помощника в этом режиме нет — `winws.exe` не понимает протокол Lua. Служба `zapret2_helper` всё равно стартует, но в режиме `--vpn-only`: она не гоняет хосты, а только следит за VPN-туннелем и при необходимости приостанавливает движки. Поэтому на вкладке Zapret мониторинг хостов для классики скрыт.

Тест доменов под классикой идёт обычным одиночным запросом — так же, как при полностью выключенном обходе. Координации по вердиктам помощника здесь нет.

Наборы — в `configs/strategy_zapret1/<поколение>/`; актуальный адаптирован из пресетов [Flowseal/zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube).

## Профили фейков

У классики есть отдельный селектор **Профиль фейков**. Профиль — это пара «бинарник подделки + домен подстановки SNI», которые подставляются в стратегию через плейсхолдеры `%FAKE_TLS%`, `%FAKE_QUIC%`, `%FAKE_TLS_DOMAIN%` и другие.

Ключи профилей лежат в `configs/fake_bin_zapret1.config`: `VK`, `GOOGLE`, `RUTRACKER`, `SHORT`, `SBERBANK`, `GOSUSLUGI`, `MAX`, `4PDA`, `SOCHI` (и другие). Сам движок перебирает их вместе со стратегиями при автоподборе: сначала все профили на текущем конфиге, потом следующий конфиг.

У Zapret2 отдельного профиля нет — блобы подключаются напрямую по имени из `configs/fake_bin.config`, а какие из них нужны, движок вычисляет по тексту стратегии.

## Как переключается движок

Переключение меняет только вид и то, что стартует дальше. Если сейчас работает другой движок, приложение предупредит, что его придётся остановить, дождётся остановки службы и только потом применит выбор. Индикатор движка на вкладке показывает, что реально запущено, а не что выбрано в селекторе.

Выбор запоминается: при следующем запуске поднимется тот движок, что был выбран, а вместе с ним — последний набор, конфигурация и (для классики) профиль фейков.

## Чем отличаются по сути

| | Zapret2 | Классический Zapret |
|---|---|---|
| Исполняемый файл | `winws2.exe` (+ `cygwin1.dll`) | `winws.exe` |
| Описание обхода | `--lua-desync` + Lua-оркестрация | статичные `--dpi-desync` |
| Перебор стратегий | адаптивный, на живом трафике | нет, что в конфиге — то и режет |
| Помощник `zapret-helper` | полноценный (проверяет хосты) | только сторож VPN |
| Профили фейков | блобы по имени из `fake_bin.config` | отдельный селектор профиля (`fake_bin_zapret1.config`) |
| Тест доменов | с учётом вердиктов помощника | обычный одиночный запрос |
| Наборы стратегий | `configs/strategy/<поколение>/` | `configs/strategy_zapret1/<поколение>/` |

## Что выбрать

| Ситуация | Движок |
|---|---|
| Первый запуск, ничего не известно | Zapret2 + Автоподбор |
| Провайдер периодически меняет правила, стратегии «отваливаются» | Zapret2 — он переключается сам |
| Нужны голосовые каналы Discord | Zapret2 — у него отдельные планы для голоса |
| Есть проверенный статичный пресет из zapret/Flowseal | Классический Zapret |
| Zapret2 не поднялся или не помогает на конкретном провайдере | Классический Zapret |

## Логи движка

Каждый движок пишет лог рядом со своим бинарником: `binaries/winws2.exe.log` для Zapret2 и `binaries/winws.exe.log` для классики. Там видно старт с конкретными аргументами и то, что движок делает дальше. Аргументы, с которыми он реально запущен, продублированы в `logs/strategy.args.txt` — этим стоит пользоваться при отладке своего конфига.

Оба движка — это только часть картины: DNS-фильтрацию снимает отдельный [DNS-прокси](DNS-прокси), а Telegram можно пустить через локальный прокси. Готовые стратегии можно дописывать самому — см. [Свои стратегии](Свои-стратегии).
