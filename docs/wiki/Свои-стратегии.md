# 🛠️ Свои стратегии

Готовые наборы — это отправная точка, а не догма: у каждого провайдера и региона своя сигнатура DPI, и часто помогает дописать свой профиль. Страница — про то, куда его класть и как устроен файл стратегии. Более глубокий разбор с полевыми находками лежит в репозитории: `docs/strategies-1.5.5.md`.

## Куда класть

| Движок | Каталог | Поколения |
|---|---|---|
| Zapret2 | `configs/strategy/<поколение>/` | `1.4.16`, `1.5.0`, `1.6.0`, `1.6.2` |
| Классический Zapret | `configs/strategy_zapret1/<поколение>/` | `1.4.10`, `1.4.16`, `1.6.2` |

Кладите `.config`-файл в уже существующий каталог поколения — он появится в селекторе конфигураций на вкладке Zapret. Новый каталог тоже подхватится: список поколений строится по содержимому папки. Каталог с файлами при обновлении приложения заменяется целиком, так что свои профили лучше держать где-то ещё и копировать после апдейта.

## Формат файла

Файл — это обычный текст, где строка = аргумент командной строки движка. Пустые строки и строки с `//` игнорируются. Секции пишутся в квадратных скобках (`[START]`, `[youtube]`, `[END]`) и служат фильтрами по портам/L7/списку хостов. Строка `use_in>>цель` включает содержимое секции в другую секцию.

Общий каркас вынесен в `configs/templates.config`: файл пишет `%TEMPLATES_<ИМЯ>%`, а генератор подставляет туда строки соответствующего блока. Блоки могут ссылаться друг на друга. Что меняется от стратегии к стратегии (пэйлоады, планы, импорты) остаётся прямо в конфиге.

Плейсхолдеры, которые разворачивает движок при загрузке конфига:

| Плейсхолдер | Во что превращается |
|---|---|
| `%BLOCKLIST%` | `--hostlist` на `user/blacklist/<секция>.list` (или `all.list` в `[START]`/`[END]`) |
| `%IP-SETLIST%` | `--ipset` на `user/ip-set/<секция>.list` |
| `%DOMAINS-EXCLUDE%` | `--hostlist-exclude` на `user/domains_exclude.list` |
| `%IP-EXCLUDE%` | `--ipset-exclude` на `user/ip-exclude.list` |
| `%INIT_LUA%` | по `--lua-init=@…` на каждый скрипт из `configs/lua_init.config` |
| `%INIT_BLOB%` | по `--blob=<ИМЯ>:@<файл>` на каждый блоб, реально использованный в стратегиях |
| `%DiscordPort%`, `%DiscordPortUPD%`, `%GamePort%` | порты из `configs/service_setting.config` |
| `%BIN%`, `%BINARIES%`, `%CONFIGS%`, `%ROOT%`, `%FAKE%` | префиксы путей |

Список хостов и ip-set собираются заново на каждом запуске из `configs/blacklist/`, `configs/ip-set/` и ваших записей в интерфейсе — поэтому правка в этих каталогах применяется сразу, а не только через конфиг.

## Номера стратегий

Это ключевая часть для Zapret2. Как только в конфиге встречается строка `--lua-desync=auto_strategy:...` (или `circular`), движок начинает нумеровать последующие `--lua-desync`-строки: каждой дописывается `:strategy=N`. Счётчик стартует заново по `--new`, а им же начинается каждая секция плана.

Правила простые, но обязательные:

- номера идут монотонно, `1..N`, **без дырок** — иначе автоперебор наступит на «пустой» номер и сломается;
- один номер могут делить несколько строк — это составная стратегия (например, `fake` + `send` + `drop`);
- явный `:strategy=N` уважается: счётчик догоняет выставленное число, ручную нумерацию можно смешивать с автоматической;
- `:final` помечает последнюю строку плана и не нумеруется.

Именно эти номера потом фигурируют в логах как `strategy_N`.

## Zapret2: `--lua-desync`

Стратегия Zapret2 — набор строк вида `--lua-desync=<функция>:<параметр>=<значение>:...:strategy=N`. Функции: `fake`, `fakedsplit`, `fakeddisorder`, `multidisorder`, `multisplit`, `hostfakesplit`, `send`, `drop`, `udplen`. Частые параметры: `blob` (какой блоб подставить), `repeats`, `badsum`, `tcp_ts`, `tcp_seq`, `tcp_md5`, `ip_id=zero`, `ip_ttl`, `ipfrag`/`ipfrag_pos_udp`, `seqovl`/`seqovl_pattern`, `pos`, `tls_mod` (`rnd`, `dupsid`, `sni=…`), `host`/`midhost`, `delay`, `strategy`.

Пример из `configs/strategy/1.6.2/strategy_super_c.config`:

```
--lua-desync=auto_strategy:start=1:fails=6:time=90:udp_out=8
--lua-desync=fake:blob=QUIC_GOOGLE:repeats=16:strategy=1
--lua-desync=fake:blob=QUIC_GOOGLE:repeats=6:strategy=2
--lua-desync=fakedsplit:seqovl_pattern=TLS_GOOGLE:seqovl=620:repeats=6:tcp_ts=-600000:strategy=9
```

Полный список функций и параметров — в документации zapret2 (`docs/readme.md` в его репозитории): движок получает эти аргументы дословно, ничего не переименовывая.

## Zapret2: блобы фейков

Стратегия ссылается на блоб по имени (`:blob=QUIC_GOOGLE`), а имя → файл задаётся в `configs/fake_bin.config`:

```
[FAKE]
TLS_GOOGLE=tls_clienthello_www_google_com.bin
QUIC_GOOGLE=quic_initial_www_google_com.bin
```

Сами файлы лежат в `binaries/fake/`. Движок сам смотрит по тексту стратегии, какие блобы реально использованы, и подключает только их. Есть и встроенные имена-заглушки: `fake_default_tls`, `fake_default_http`, `fake_default_udp`, `fake_default_quic`. Если сослаться на блоб, которого нет в `fake_bin.config`, в лог упадёт предупреждение с именем ключа.

Часть этих файлов приезжает из payload zapret2, и сборка обновляет их при каждой сборке движка. Так что свой блоб кладите **под своим именем** и описывайте ключом в `fake_bin.config` — правку файла, который есть в payload, следующая сборка затрёт.

## Классический Zapret: `--dpi-desync`

Здесь примитивы статичные: `--dpi-desync=fake`, `multisplit`, `disorder`, `fake,split2` и т.д., а модификаторы идут отдельными ключами — `--dpi-desync-repeats`, `--dpi-desync-split-pos`, `--dpi-desync-split-seqovl`, `--dpi-desync-any-protocol`, `--dpi-desync-cutoff`, `--ip-id=zero`. Файловые аргументы классический движок принимает через пробел, а не через `=`; движок делает эту замену сам.

Фейки задаются плейсхолдерами из `configs/fake_bin_zapret1.config`, а какой профиль активен — решает селектор «Профиль фейков» в интерфейсе:

```
--dpi-desync=fake
--dpi-desync-repeats=6
%FAKE_QUIC%
```

Плейсхолдеры: `%FAKE_TLS%`, `%FAKE_QUIC%`, `%FAKE_TLS_DOMAIN%`, `%FAKE_HOST_DOMAIN%`, `%FAKE_HTTP%`, `%FAKE_DISCORD%`, `%FAKE_STUN%`, `%FAKE_UNKNOWN%`, `%FAKE_CLIENT_HELLO%`, `%FAKE_INITIAL%`, `%SEQOVL_PATTERN%`. Ключи профилей — `VK`, `GOOGLE`, `RUTRACKER`, `SHORT`, `SBERBANK`, `GOSUSLUGI`, `MAX`, `4PDA`, `SOCHI`.

## Как проверить, что получилось

При загрузке конфига движок прогоняет строки через нормализацию: разворачивает порты служб, вычищает оставшиеся `%…%`-макросы, убирает пустые элементы перечислений и хвостовые лишние `--new`. Итоговая команда целиком пишется в `logs/strategy.args.txt` — это самый быстрый способ убедиться, что ваш конфиг собрался в то, что вы имели в виду. Рядом, в `binaries/winws2.exe.log` (или логе `winws.exe` для классики), видно, как движок реально стартовал.

> [!WARNING]
> Если конфиг ссылается на несуществующий файл блоба или `%INIT_BLOB%` не находит нужного ключа — движок либо не стартует, либо стартует без нужной стратегии. Проверяйте `logs/strategy.args.txt` после правки.

## Поделиться профилем

Сложите рабочий файл в обсуждения — [категория «Конфигурации»](https://github.com/MagilaWEB/unblock-youtube-discord/discussions/categories/конфигурации). Чтобы помощь пришла быстро, укажите провайдера, регион и что именно не работало без этого профиля. Про природу блокировок и полевые находки полезно почитать `docs/strategies-1.5.5.md` в репозитории — там же разобрано, почему у стратегий разные потолки на разных хостах.
