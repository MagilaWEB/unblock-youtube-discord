# 🔧 Разработка: сборка и тесты

Сборка — clang + Ninja, конфигурация через CMake-пресеты. Агентская сборка живёт в отдельном каталоге `_build_ai` и не путается с IDE-шной `_build`.

## Пресеты и скрипты

`CMakePresets.json` описывает пресеты `debug`, `release`, `debug-min`, `release-min`. Компиляторы — `clang`/`clang++`, ресурсник — `llvm-rc`, `compile_commands.json` включён. Пресеты `*-min` выставляют `BUILD_TESTS=OFF`; их бинарные каталоги — `_build/debug`, `_build/release` и т.д. (это каталоги IDE).

Обёртки в корне репозитория:

| Скрипт | Что делает |
|---|---|
| `configure-ninja-ai.bat` | чистая конфигурация `_build_ai` пресетом `debug` через Ninja (зовёт `configure-ai.bat`) |
| `build-ai.ps1` | конфиг при необходимости + сборка; параметры `-Preset`, `-Clean`, `-Target`, `-VersionOverride` |
| `test-ai.ps1` | `ctest --test-dir _build_ai --output-on-failure`, можно сузить через `-Name` |
| `fmt-ai.ps1` | clang-format: изменённые файлы из `git status`, либо всё (`-All`), либо проверка (`-Check`) |
| `tidy-ai.ps1` | clang-tidy с `-p _build_ai`; `-All`, `-Fix`, `-Filter`, `-Checks`, `-Jobs` |
| `release-ai.ps1` | сборка `release-min` и упаковка релиза — см. [Релиз и версии](Разработка-Релиз-и-версии) |
| `sync-wiki-ai.ps1` | выливает страницы из `docs/wiki/` в GitHub-вики: клон в `%TEMP%`, зеркалирование страниц, коммит и пуш |
| `build-tgws-ai.ps1` | собирает консольный `tg-ws-proxy.exe` из релиза [Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy) и кладёт его в `binaries/`; запускается руками, в сборку не встроен — детали в [CONTRIBUTING.md](https://github.com/MagilaWEB/unblock-youtube-discord/blob/main/CONTRIBUTING.md) |

`build-ai.ps1` перед работой чистит `$env:INCLUDE/$env:LIB/$env:LIBPATH` — иначе clang подхватывает MSVC-окружение и путается. Конфигурирует он только когда это нужно: сравнивает закешированные `CMAKE_BUILD_TYPE` и `BUILD_TESTS` с ожидаемыми для пресета и передаёт `BUILD_TESTS` явно — опция кешируемая, без этого переключение `debug`/`debug-min` не срабатывало бы. Смена `-VersionOverride` тоже форсит реконфиг.

Обычный цикл:

```powershell
pwsh -NoProfile -File build-ai.ps1
pwsh -NoProfile -File test-ai.ps1
```

Сборка одной цели — `build-ai.ps1 -Target <имя>`.

## Почему первый конфиг долгий

Зависимости тянутся через FetchContent и собираются из исходников: saucer, curl + zlib (статически, Schannel, HTTP-only), bit7z, 7za, сам zapret2 и zapret-win-bundle для `winws.exe`, AdGuard DnsLibs, Catch2. Первая конфигурация может идти долго; дальше CMake переиспользует `_deps`.

`CMAKE_RUNTIME_OUTPUT_DIRECTORY` указывает на `<repo>/bin`, поэтому `engine.exe`, `zapret_helper.exe`, `unblock_dns.exe`, `unblock_update.exe` и DLL-зависимости появляются в `bin/`. Каталог `binaries/` наполняется POST_BUILD-шагом цели `engine` прямо из payload: `winws2.exe`, `cygwin1.dll` и Lua-скрипты из zapret2, `winws.exe` из zapret-win-bundle, `WinDivert.dll` с `WinDivert64.sys` оттуда же, плюс фейк-блобы, которые называют `configs/fake_bin.config` и `configs/fake_bin_zapret1.config`. Свои блобы, которых в payload нет, сборка не трогает.

Вручную обновляются только два бинарника: `SvcHost.exe` (из [MagilaWEB/svc_host](https://github.com/MagilaWEB/svc_host)) и `tg-ws-proxy.exe` — консольную сборку [Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy) делает `build-tgws-ai.ps1`, запуск руками, в сборку проекта он не встроен (подробности — в `CONTRIBUTING.md`).

Статический рантайм (`/MT`, `/MTd` для debug) вшит в бинарники — зависимости от системного `vcruntime140*.dll` нет.

## `import std` и модуль стандартной библиотеки

CMake-овский `import std` для clang умеет только с libc++/libstdc++, а тут ABI MSVC. Поэтому проект собирает собственный модуль `ub_std` из MSVC-шного `std.ixx`: он объявлен обычным `CXX_MODULES`-файлом, гейт `CMAKE_EXPERIMENTAL_CXX_IMPORT_STD` не нужен. Патч-скрипт `cmake/MsvcStdModule.cmake` держит `std.ixx` в рабочем виде:

- добавляет `<vcruntime_new.h>` в глобальный фрагмент (clang неявно объявляет `std::align_val_t` — llvm/llvm-project#214354);
- возвращает `_VCRT_EXPORT_STD` в `export`, иначе `std::exception`/`std::bad_alloc` из модуля не видны.

Файл нужно обновлять при смене тулсета: путь к `std.ixx` ищется по списку инклудов компилятора.

## Тесты

Тесты — Catch2 v3 с TAP-репортером, свой exe на модуль: `src/<module>/tests/`. Тесты линкуют библиотеку модуля, а не компилируют его исходники (файлсет модулей принадлежит одному таргету). `test_helper` линкует `core`, потому что общий `tap_main.cpp` тянет конструкторы `File`/`CriticalSection`. Catch2 подключается текстуально до импортов.

Доступ к приватным членам — friend-харнесс под `#ifdef HELPER_TESTS`/`UNBLOCK_TESTS` (макрос задаётся только при `BUILD_TESTS`). Класс-харнесс объявлен в `src/<module>/tests/test_forwards.h`, а этот заголовок включается и в глобальном фрагменте тестируемого модуля, и в тесте до импортов — иначе friend и определение класса окажутся разными сущностями.

Отдельно от ctest гоняется проверка версионирования: тест `version_conventions` вызывает `cmake/tests/TestConventionalVersion.cmake` с чистыми функциями бампа.

## Грабли: реконфиг чистит `bin/`

Конфигурация проекта удаляет `bin/` (так задумано в `src/engine/CMakeLists.txt`) — иначе инкрементальная сборка стирала бы туда скопированные DLL. Беда в том, что ninja считает удалённые, но «актуальные» файлы свежими и не перелинковывает их: `zapret_helper.exe`, `unblock_dns.exe` и тестовые exe остаются отсутствующими, а `ctest` показывает `Not Run`. Поэтому `build-ai.ps1` после сборки разбирает `build.ninja`, находит выходы в `bin/` и досоздаёт те, которых нет. Ручной вариант — `cmake --build _build_ai -j 2` после чистки переменных окружения, если clang упал по памяти.

## Lua применяется только после сборки

Скрипты правятся в `resources/lua/`, а в рантайме движок грузит их из `binaries/lua/` — копия делается пост-сборкой цели `engine`. Пока не собрались, правка Lua не действует. То же с `configs/`: они используются из папки установки, а не из репозитория.

## Диагностика сборки

| Симптом | Что делать |
|---|---|
| clang падает по памяти (OOM) | очистить `$env:INCLUDE/$env:LIB/$env:LIBPATH` и `cmake --build _build_ai -j 2` |
| `ctest` показывает `Not Run` | либо тестовые exe снесены реконфигом — соберите (`build-ai.ps1` досоздаёт выходы `bin/`), либо в кеше остался `BUILD_TESTS=OFF` от `*-min`-пресета: `build-ai.ps1` теперь проставляет значение явно при переконфиге |
| Пропал `zapret_helper.exe`/`unblock_dns.exe` | тот же случай: ninja считал их свежими, `build-ai.ps1` досоздаёт |
| Висят процессы `rc.exe`/`cl.exe` | в окружении остались MSVC-переменные; скрипты их чистят сами |
| Странная версия в сборке | застрявший `-VersionOverride` в кеше: `build-ai.ps1` без флага снимет его реконфигом |

Полный `-Clean` удаляет `_build_ai` и конфигурит заново — после него первый билд снова долгий из-за FetchContent.

## Прочее

- clang-tidy: `tidy-ai.ps1` сам продлевает `Path` до `C:\Program Files\LLVM\bin` и чистит MSVC-переменные; модульные флаги он берёт из modmap в `compile_commands.json` (`-p _build_ai`), `.cppm` тоже проверяет.
- Формат — `.clang-format` (база Microsoft, табы, `ColumnLimit 150`, CRLF, `SortIncludes: Never`), прогон `fmt-ai.ps1`.
- Мусор не индексируется и не форматируется: `_build_ai/`, `_build/`, `_deps/`, `bin/`.
